# v0.52.0

**Release Date:** 2026-09-13

Integrate tinyfly into any page the way you would GSAP.

Phase 27C.6. The engine could already be imported from a bundler, but there was
no `<script>`-tag build with a GSAP-shaped API, and animating a real element
meant building a timeline, mapping target names to elements, and starting a
loop. This release closes that gap and prepares the package for npm.

## Added

### `live`: GSAP-style calls that play straight away

```ts
import { live } from 'tinyfly/gsap-compat'

live.to('.box', { x: 200, duration: 1, ease: 'power2.out' })
live.from('.card', { opacity: 0, y: 30, duration: 0.6, stagger: 0.1 })

live.timeline({ repeat: -1, yoyo: true })
  .to('#a', { x: 120, duration: 0.5 })
  .to('#b', { rotate: 180, duration: 0.5 }, '<')
```

- Targets are CSS selectors, elements, node lists, or arrays of them. A
  selector that matches several elements animates all of them, and `stagger`
  fans them out.
- Playback starts on the next microtask, so every tween chained synchronously
  onto a timeline is in place first. `paused: true` opts out.
- Timelines chain and have the usual controls: `play`, `pause`, `resume`,
  `restart`, `reverse`, `seek`, `progress`, `timeScale`, `kill`.
- `live.to(target, { repeat, yoyo, onStart, onUpdate, onComplete })` accepts
  those options on the tween itself, as GSAP does.
- `toDefinition()` returns the same plain JSON the compiler produces.

### Concurrent animations compose

Every `live` animation shares one `Stage`, with one frame loop and one DOM
adapter. The stage merges values per element before writing, so

```ts
live.to('#box', { x: 200, duration: 1 })
live.to('#box', { rotate: 90, duration: 1 })
```

moves *and* turns the box. Before this, two independent players each wrote a
`transform` that left out the other's property. The loop stops when nothing is
playing.

A new tween starts from the value tinyfly last applied to that element. This
value is resolved once, when the tween is built, and it never reads the DOM,
so the determinism rules in `docs/gsap-compat.md` still hold.

### One bundle for `<script>` tags

```html
<script src="https://cdn.jsdelivr.net/gh/algorisys-oss/tinyfly@v0.52.0/cdn/tinyfly.iife.js"></script>
<script>
  tinyfly.to('.box', { x: 200, rotate: 90, duration: 1 })
</script>
```

`lib/browser/tinyfly.{iife,umd}.js` (about 29 KB gzipped) contains the engine,
player, `live`, `tf`, drivers and interaction behind a single `tinyfly` global.
It is also available to bundlers as `tinyfly/browser`, although the individual
entry points tree-shake better.

### One Examples page

The editor used to have two places for ready-made animations, and they
overlapped. The **Samples** dialog loaded editor projects, and a separate
**Examples Gallery** page (in the More menu) showed previews that could not be
opened. Both are now one page, `/examples`, reached from a single **Examples**
button on the toolbar.

- **Editable examples** open in the editor. **Open in editor** now creates a
  **new project**. The old dialog replaced the current project, so loading a
  sample could overwrite your work.
- **Code examples** show their timeline JSON and HTML under **View code**, and
  play on DOM or Canvas.
- Each card shows a still frame and plays while you hover. Editable previews use
  the same HTML generator as embeds, so a preview matches what an embed shows.
- There is search, plus filters for kind (All / Open in editor / Code) and for
  category. The filters are kept in the URL, so
  `/examples?kind=code&category=scroll` can be linked to.
- `/gallery` redirects to `/examples`.

### GSAP-style examples

A new **GSAP-style** category with fourteen runnable demos written with `live`:

| Demo | Shows |
|---|---|
| Staggered Grid | One selector, 24 elements; `stagger: { from: 'center' }`, `back.out`, yoyo |
| Logo Sequence | Labels and position parameters (`'-=0.25'`, `'text+=0.15'`, `'>0.4'`) |
| Composed Tweens | Separate tweens on one element combining, each with its own duration |
| Timeline Controls | `play`, `pause`, `reverse`, `timeScale`, and a `progress()` scrubber |
| Pointer Follow | A new tween for every pointer move, continuing from where the dot is |
| Elastic, Bounce & Steps | Eases with no bezier form, sampled into keyframes by `bakeEases` |
| Magnetic Button | Leans toward the pointer; snaps back with `elastic.out` |
| Proximity Grid | Scale by distance to the pointer; `kill()` the previous tween per dot instead of `overwrite` |
| Dock Magnify | macOS-style magnification from a bottom transform origin |
| Velocity Skew | `skewY` from scroll velocity, settling back to flat |
| Card Stack | Click-to-cycle cards, sequenced with `onComplete` |
| Infinite Marquee | A seamless `repeat: -1` loop, slowed with `timeScale()` on hover |
| Split Text Reveal | Per-character 3D entrance, a wave, and an exit from the end |
| SVG Line Draw | `strokeDashoffset` line drawing, recoloured through `currentColor` |

The last eight recreate popular effects from the
[GSAP demo hub](https://demos.gsap.com/). The code is written from scratch on
tinyfly. In Chrome they were driven with real pointer, scroll and click input,
and the proximity grid held 60 fps while the pointer swept across it.

A demo runs while you hover over its card, on a stage whose selectors only match
inside that card, and resets when the pointer leaves. The code on the card is
read from the demo's source file, so it is exactly the code that runs.

### Copy code

Every example card has a **Copy code** button. It copies a complete HTML page
that you can save and open: the markup, its styles, the animation, and the
tinyfly script tag.

- **GSAP-style:** the demo's code, unchanged. Demos are written in plain
  JavaScript so the copied code runs without a build step.
- **Timeline:** the timeline JSON plus `tinyfly.play()`. Scroll examples include
  their scroll setup as a comment.
- **Editable:** the same markup and animation the editor's Embed produces.

The page loads the bundle from the GitHub CDN, pinned to the version that
produced it (see below).

`Stage.destroy()` is new. It stops everything on a stage, releases its
elements, and ignores any autoplay still queued.

### A CDN from GitHub

tinyfly can be used from a `<script>` tag without npm. Each release builds the
browser bundles from the exact source it publishes, commits them to `cdn/` in
[algorisys-oss/tinyfly](https://github.com/algorisys-oss/tinyfly), and tags the
commit `v<version>`. jsDelivr serves them from there:

```
https://cdn.jsdelivr.net/gh/algorisys-oss/tinyfly@v0.52.0/cdn/tinyfly.iife.js
https://cdn.jsdelivr.net/gh/algorisys-oss/tinyfly@v0.52.0/cdn/tinyfly.esm.js
https://cdn.jsdelivr.net/gh/algorisys-oss/tinyfly@v0.52.0/cdn/tinyfly-player.iife.js
```

The publish script never moves an existing tag, so the files at a pinned URL
never change. The OSS repo's `package.json` also keeps the library build
scripts now; they were previously removed during publishing.

## Changed

- `package.json` is ready to publish: `private` is removed, and it now has
  repository, keywords, `unpkg`/`jsdelivr` fields and a `prepublishOnly` step
  that tests and builds. Solid and the router moved to `devDependencies`,
  because the published package is the engine and has no runtime dependencies.
  Nothing has been published to npm yet.
- `CompatTimeline` takes an optional `startValue(target, property)` hook. The
  resolution chain consults it after the timeline's own last value and before
  `defaults`.

## Fixed

- The three Camera samples (Push In, Pan Across, Orbit Reveal) never appeared in
  the Samples dialog, because its category list left out `camera`. They are now
  in the Camera category on the Examples page.

## Removed

- The Samples dialog, and **Examples Gallery** in the More menu. Both are
  replaced by the Examples page.

### Test Coverage

- 102 new tests for Copy code. Every generated page (all 82 examples) is checked
  for a complete document, the bundle, and a script that compiles. The 14
  GSAP-style pages are also run, with simulated pointer and scroll input,
  and have to move something. In Chrome, four
  copied pages were saved and opened standalone, and all of them animated.
- 20 new tests for the GSAP-style demos and `Stage.destroy()`. Each demo runs
  against its own markup, has to move something, and has to tear down without
  errors. All fourteen were also run in Chrome: each animated, reset on leave, and
  logged no console errors.
- 15 new tests for the Examples page. They check that the catalog includes
  every sample and every code example, that ids are unique across both, that
  filtering works, that every editable example previews with a target for
  each animated element, and that `applySample` loads motion paths.
- Checked in headless Chrome against the dev server: `/gallery` redirects,
  68 examples render, hover plays a preview, the filters and **View code**
  work, and **Open in editor** adds a project (1 → 2) without touching the
  existing one and without adding another on reload.
- 19 new tests. They cover live playback with a manual frame scheduler,
  transform composition, start values carried over, autoplay and cancelling
  it, pause/resume/reverse, zero-length `set`, and the `startValue` hook.
- Checked in headless Chrome from a plain `<script>` tag: two tweens on one
  element composed, the stagger ran across the matched elements, and
  `onComplete` fired.

### Caveats

- Elements stay registered with a stage once they have been animated. In a
  long-lived single-page app, use one `Stage` per view.
- Only `live` shares a loop. `quickPlay`, the player and the drivers still run
  their own.
