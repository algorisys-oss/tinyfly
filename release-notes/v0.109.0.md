# v0.109.0 — Cricket stories on the organic rig

Released: 2026-10-13

Create reusable cricket demonstrations from JSON APIs, using the same organic
adult and child characters as the live story examples. An interactive example
offers Test, ODI and T20, event seeking and camera controls around the ground.

## Added

- `@algorisys/tinyfly/sports`: `cricketPlayer`, `cricketField`, `cricketAction`,
  `cricketClip`, `cricketCameraTracks`, `cricketEventAt` and shared
  `ballFlightPoint` / `ballFlightTracks`.
- Standard pitch, creases, wickets and bails, boundary, eleven fielding players,
  two batters and two umpires. Adults, children and mixed casts, editable
  uniforms and appearance, optional headwear.
- Sixteen authored plays: pace/spin bowling, drive, block, running, four, six,
  catch, ground fielding, throw, bowled, LBW, stumping, run-out, no-ball and wide.
- Contact-keyed bat grips, ball releases/receives, wicket breaks and umpire
  signals. Events, captions and declared example results remain plain JSON.
- Eight camera views: pitch, batter, bowler, keeper, whole ground, overhead,
  full 360° orbit and ball follow. JSON download includes selected camera tracks.
- Cricket guide, generated capability discovery and a headless video example.

## Fixed

- Keeper-bound pace, spin, no-ball and stumping deliveries pass clear of intact
  striker stumps, including the displayed ball radius, before palm collection
  on adult, child and mixed casts. Bowled and later stumping contacts remain.
- Wide cricket cameras keep the pitch, wickets, ball and outfield inside the
  clipping range for boundaries up to 250 m. Equivalent static azimuths use
  identical camera geometry.
- Ball-follow camera generation samples only the ball position channels with
  forward keyframe cursors, avoiding repeated evaluation of dense actor tracks.
- Development full-page live previews include the local browser API and scene,
  WebGL and maps add-ons; production and copied pages keep versioned CDN URLs.
- The cricket headless example documents the supported `-o` output option.
- Drive and ground-fielding plays have distinct collection paths while keeping
  rendered palm contact on adult and child rigs.
- Browser checks start an owned server on an available port, reject occupied
  explicit ports and fail if that server exits, avoiding stale-server results.

## Validation

- Defensive blocks have focused two-hand pose, blade-contact and narration
  regressions. Continuous ball-segment clearance checks cover all three casts,
  sparse sampling and scaled durations, plus intentional bowled collisions.
- Deterministic finite JSON tracks for all plays, valid scene channels and
  format outcomes; palm release, grounded bowling foot, two-hand bat grip,
  blade contact, catch and stumping contacts on adult and child rigs.
- Camera orbit closure, ball following, event seeking, controls, copied code,
  mobile layout and downloadable scene/action/camera JSON.
- Maximum ground clipping, ball-only linear keyframe access, equivalent yaw
  geometry and local add-on previews have focused regressions. Browser checks
  distinguish all sixteen plays across delivery, contact and result phases.
- 3,687 tests in 236 files, application/library type checks, add-on builds and
  87 focused Chromium, Firefox and WebKit cricket checks pass.
- Deployed-page checks pass in all three browsers using the published CDN.
  Published builders run in a Web Worker and a fresh npm consumer in Node.
- Authored educational demonstrations; ball physics, automatic umpiring,
  complete innings and guided lessons are left to the consuming application.
