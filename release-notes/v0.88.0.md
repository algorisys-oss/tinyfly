# v0.88.0

**Release Date:** 2026-10-05

Light trails: comets and light streaks on any 2D canvas, and lines and
trails inside 3D scenes, sorted by depth among the meshes.

## Added

- **`trailSamples(positionAt, time, { length, samples, period, since })`**
  (engine): where something was over the last `length` ms, oldest first, each
  with its age. It asks a function of time (usually the timeline), never a
  history of frames, so seeking, scrubbing, frames in any order and loops all
  draw the same trail. `period` wraps earlier times, so a loop's first frame
  already has the last lap's tail.
- **`drawTrail(ctx, samples, style)`** (`@algorisys/tinyfly/adapters` and the
  browser bundle): a band that narrows (`taper`) and fades (`fade`) toward the
  tail, with a round head and an optional glowing comet `head`. One strip of
  segments sharing their corners, built additively: smooth at any speed, no
  beads, no seams. `blend: 'add'` adds light, brighter where trails cross.
- **`ribbon(points)` / `ribbonHeadCap(points)`**: the band's geometry, for
  other renderers.
- **3D `line` and `trail` objects**: a polyline through `points` (`closed?`),
  and a band through where another object (`follow`) has been. `width` in
  metres, `taper`, `fade`, `opacity`, `blend`. Every segment sorts by its own
  depth among the triangles, so a trail passes behind one shape and in front
  of another; fog dims the far side; bands are cut at the near plane.
  `color`, `width`, `opacity` and (trails) `length` animate.
- **`valuesAt`** on `resolveScene3D`, `drawScene3D` and `Scene3DAdapter`:
  the values at another time, for trails.
- **`FrameInfo.stateAt(time)`** for video scenes: the timeline's state at any
  time. `drawScene3D(ctx, scene, frame.state?.values, frame)` passes it on,
  so trails in videos need no extra wiring.
- Demos: **Light Trails** (Effects) and **3D Scene: Comet Trails** (3D).
  Example `examples/headless-video/comet-trails.mjs`, a looping comet video.

## Upgrade Notes

- **No breaking API changes.**
- `Object3D` gains the `line` and `trail` kinds: code that switches over
  every kind may want to handle them.
- With the WebGL2 renderer, lines and trails are drawn on the overlay, in
  front of the meshes. The editor's 3D element has no fields for them yet.
