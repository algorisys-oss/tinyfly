# v0.83.0

**Release Date:** 2026-10-05

3D, first steps. tinyfly can now draw real 3D scenes: cameras, lights and
meshes as JSON, animated by ordinary tracks, drawn on a plain 2D canvas in a
stylized look (toon bands, ink outlines, fog), in the browser and to MP4 in
Node, with no WebGL. Flat things (cards, images, text) turn in 3D with true
perspective in every renderer, matching the browser's own CSS. Rotations can
be quaternions that turn the short way round. This is milestones 0 to 2 of the
[3D plan](../docs/3d-support-plan.md), which also now covers films, in a
stylized and a realistic look.

## Added

- **3D scenes**, `@algorisys/tinyfly/scene-3d` (and `tinyfly-scene-3d.iife.js`
  for script tags, about 7 KB gzipped):
  - `Scene3D` as JSON in metres (+y up): groups; meshes (box, sphere,
    cylinder, cone, torus, a floor plane, and `extrude`: any SVG path made
    solid, holes and all); perspective and orthographic cameras with
    `lookAt`; ambient, directional, point and spot lights; materials with
    fields for the stylized and the realistic look; fog; `layer` for draw
    order.
  - Tracks at `<sceneId>/<objectId>` move, turn (Euler or quaternion), scale,
    show, fade and recolour objects, light lights and zoom cameras; an
    `activeCamera` track on the scene cuts between cameras with one keyframe.
  - `validateScene3D`, `loadScene3D`, a pure `resolveScene3D` (world matrices,
    culling, near-plane clipping, a total draw order, silhouette and crease
    outlines), `Canvas2DRenderer`, `Scene3DAdapter`, `drawScene3D` (for a
    video's `draw` hook), `orbitPosition`, `dollyPosition`.
  - Shading: unlit, flat, lambert (smoothed), toon (banded brightness).
- **CSS-style 3D in every renderer**: `rotateX`, `rotateY`, `z`,
  `perspective`, `quaternion` and `backfaceVisibility` on DOM, SVG, Canvas
  (true perspective through a seamless triangle mesh, also headless) and
  WebGL (a 4×4 matrix per quad); DOM `childPerspective` and
  `perspectiveOriginX/Y` for a parent's shared vanishing point.
- **Rotations and 3D math** in the engine: `vec3`, `quat` (YXZ Euler order)
  and column-major `mat4` as plain arrays; `Track.interpolation: 'slerp'` for
  quaternion tracks (file format version 2, written only when used).
- **Editor**: a 3D section (Tilt X, Turn Y, Depth, Perspective, keyed at the
  playhead); 3D Card Flip and Cover Flow samples.
- **Examples**: a **3D** pill (Quaternion vs Euler, 3D Scene: Orbiting
  Camera, 3D Card Flip, Cover Flow, and the GSAP-style Card Flip and Split
  Text Reveal, which stay under GSAP-style too).
- **gsap-compat**: GSAP's 3D names (`rotation`, `rotationX/Y/Z`,
  `transformPerspective`, a parent's `perspective`); `quaternion` tweens
  are slerped.
- `examples/headless-video/scene-3d-orbit.mjs`: an orbit and a camera cut,
  rendered to MP4 in Node.
- Docs: [3D Scenes](../docs/scene-3d.md), [3D Transforms and Rotations](../docs/3d-rotations.md).

## Changed

- **The DOM adapter writes transforms in one fixed order** (perspective,
  translate, rotate, rotateX, rotateY, quaternion, scale, skew), the order
  the SVG and Canvas adapters already used, instead of the order tracks were
  added. A DOM animation that added, say, `rotate` before `x` now draws as
  it always did on Canvas.
- **Canvas `rotateX` / `rotateY`** are exact 3D projections: a single turn
  looks as before; both together now shear correctly.
- **`perspective: 0` is no perspective** in every renderer (CSS clamped it
  to 1px).
- **gsap-compat `perspective`** means the parent's perspective for its
  children, as in GSAP (`transformPerspective` is the element's own).

## Fixed

- The e2e demos check counts canvas pixels, not only markup (Dressed Stick
  Figures was reported static).

## Technical Details

| File | Description |
|------|-------------|
| `src/engine/math/` | `vec3`, `quat`, `mat4` |
| `src/adapters/transform-3d.ts` | The CSS 3D matrix, perspective mesh, backfaces (Canvas and WebGL) |
| `src/scene-3d/` | Scene types, validation, primitives, extrude, triangulation, resolver, shading, Canvas 2D renderer |
| `src/entry-boundaries.test.ts` | The engine and player never reach 3D code; scene-3d never reaches WebGL, glTF or three |
| `e2e/checks/transforms-3d.mjs` | DOM, Canvas and WebGL against the browser's CSS in Chromium, Firefox and WebKit |

## Upgrade Notes

- **No breaking API changes.** Files without slerp tracks stay format
  version 1; a file with them is version 2, which older readers refuse with
  a clear message.
- Check DOM animations whose transform tracks were added in an unusual order
  (see Changed).
- Next on the 3D plan: 3D characters, a WebGL2 renderer, glTF import.
