# v0.17.0

**Release Date:** 2026-07-22

Minor release that makes raster export **real**: working animated **GIF**, new
animated **WebP**, and deterministic **MP4** via WebCodecs — all dependency-free,
all driven from the Export dialog.

## Highlights

- **GIF export actually works now.** The previous encoder quantized each frame to
  a palette and then wrote a hardcoded **greyscale** colour table, so every GIF
  came out grey; its LZW coder also never re-emitted a clear code, corrupting
  larger frames. Both are fixed: median-cut quantization with optional
  Floyd–Steinberg dithering, a per-frame local colour table, correct transparency,
  and a spec-conformant LZW stream.
- **Animated WebP export (new).** Roughly **3× smaller than the equivalent GIF**
  with true colour and full alpha. The browser's native still-WebP encoder does
  the compression; tinyfly re-muxes those frames into a `VP8X`/`ANIM`/`ANMF`
  container.
- **MP4 via WebCodecs, with a hand-written muxer.** H.264 frames are encoded one
  at a time and muxed into a real MP4 (`ftyp`/`mdat`/`moov` with full sample
  tables). Unlike MediaRecorder this is **not real-time** — it runs as fast as the
  machine allows and timestamps every frame exactly, so the same timeline always
  produces the same file. MediaRecorder remains as a fallback.
- **Sharper video.** Exports default to **2x resolution**, and both encoders now
  target ~0.25 bits/pixel/frame instead of MediaRecorder's much lower default —
  the previous blurriness on text and flat vector art is gone.
- **One export UI for all raster formats** — resolution, FPS, background colour
  or transparency, per-format quality controls, live progress, and Cancel.

## Added

- `exportToWebP()` / `WebPEncoder` / `parseWebPBitstream()` — animated WebP.
- `exportToMP4()` / `muxMP4()` / `pickAVCCodec()` — WebCodecs H.264 + MP4 muxer.
- `exportVideo()` + `getVideoExportFormats()` — picks the best engine available
  and reports whether it is deterministic.
- `GIFEncoder` (with `dither` and `maxColors` options); `SimpleGIFEncoder` is
  kept as a deprecated alias.
- `buildPalette()` / `quantizeImage()` / `PaletteMatcher` — reusable colour
  quantization; `ByteWriter` — shared binary writer.
- Export dialog: WebP tab, working GIF tab, resolution multiplier, background /
  transparency controls, progress bar and Cancel.

## Changed

- `exportToGIF()` is now async and accepts `dither`, `maxColors`, `onProgress`
  and `signal`; its `renderFrame` callback may return a promise.
- `exportToVideo()` (MediaRecorder) now takes an explicit `bitrate`, defaulting
  far above the browser default.
- GIF/WebP/MP4 exports render at the chosen resolution with
  `imageSmoothingQuality = 'high'`.

## Fixed

- **Restored animations wouldn't play after a page reload.** Track and keyframe
  edits mutate the *same* `Timeline` instance and signal through a separate
  version counter, but the auto-save effect only read `store.state.timeline` — a
  reference that never changes. Timeline edits therefore scheduled no save, and a
  reload restored a stale or empty timeline. The effect now subscribes to the
  mutation counter, and the scene is flushed on `beforeunload` /
  `visibilitychange` so the 1s auto-save debounce can't swallow the last edit.
- **Exports ignored the artboard background.** The preview background was a
  hard-coded CSS rule rather than project data, so exports had nothing to read and
  fell back to white. `background` is now part of `ProjectCanvas`: it drives the
  preview, is editable in **Project Settings**, serializes with the project, and
  is the default background for GIF/WebP/MP4 export. Projects saved before this
  release are migrated to the previous `#252525`.
- **GIF colours** — output is no longer greyscale.
- **GIF LZW corruption** — the code-size increase happened one step too late, so
  a decoder (which builds its dictionary one entry behind the encoder) desynced
  at the 512-code boundary and garbled every frame past ~256 distinct pixels.
- **Blurry MP4** — low default bitrate plus 1x export resolution.

| File | Description |
|------|-------------|
| `src/engine/export/quantize.ts` | Median-cut palette + Floyd–Steinberg dithering + cached nearest-colour matching |

### Test Coverage

- 590 tests passing (+46).
  - GIF: 19 tests — output is **decoded back to pixels** and checked for colour,
    transparency, per-frame delays, loop count and sub-block framing, rather than
    only asserting the blob is non-empty (which is how the greyscale bug survived).
  - MP4: 16 tests — box tiling, `mdat` contents, `stco`/`stsz`/`stts`/`stss`/`stsc`
    tables, and the embedded `avcC` record.
  - WebP: 16 tests — chunk layout, VP8X flags, frame durations, alpha ordering and
    even-length padding.
  - Project store: 5 tests — canvas background default, explicit background,
    dimension-only updates preserving the background, and migration of projects
    saved before the field existed.

### Verified in a real browser

Unit tests cannot prove a container is playable, so all three formats were run
end-to-end in headless Chrome via `export-check.html`:

- **GIF** — decoded back to pixels; colours exact, frames genuinely differ.
- **WebP** — the browser decoded the muxed file as a 320×240 image.
- **MP4** — a `<video>` element loaded it (320×240, duration 1.00s) and a seeked
  frame decoded to the expected content.

### Known limitations (tracked in todo.md)

- MP4 requires WebCodecs (Chrome/Edge/Safari 16.4+); Firefox falls back to
  real-time WebM recording.
- WebP export needs a browser that can encode `image/webp` from a canvas.
- MP4 has no alpha channel — transparency applies to GIF and WebP only.
- The muxer writes a 32-bit `mdat`, so exports are capped at 4GB.

## Upgrade Notes

Upgrade from v0.16.0:

1. Projects gain a `canvas.background` field, defaulted to the previous
   `#252525` on load — no action needed.
2. `exportToGIF()` is now **async** (it returned a promise before, but now awaits
   `renderFrame`). Existing `.then()` callers are unaffected.
3. `SimpleGIFEncoder` still works but is deprecated in favour of `GIFEncoder`.
4. `setCanvas()` / `createNew()` accept `ProjectCanvasInput`, where `background`
   is optional; passing only `width`/`height` no longer resets the background.
