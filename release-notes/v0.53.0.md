# v0.53.0

**Release Date:** 2026-09-13

This release adds most of the engine work needed to rebuild the GSAP demos in
tinyfly: motion paths, shape morphing, text animation (typing and scrambling),
inertia (throws, with dragging), and a fix to how the engine resolves several
tracks on one property. Before the
fix, chained tweens on the same property silently hid each other.

## Added

### Motion paths from `live`, `tf` and `timeline()`

GSAP's `motionPath` option:

```ts
live.to('.plane', {
  motionPath: { path: '#route', align: '#route', autoRotate: true },
  duration: 3,
  ease: 'power1.inOut',
})

live.to('.dot', { motionPath: [{ x: 0, y: 0 }, { x: 80, y: -40 }, { x: 160, y: 0 }], duration: 2 })
```

- **`path`** can be SVG path data or an array of `{ x, y }` points (with
  `curviness`). In `live` it can also be a selector or element for a `<path>`,
  `<circle>`, `<ellipse>`, `<rect>`, `<line>`, `<polyline>` or `<polygon>`.
- **`autoRotate`** turns the follower to face along the path. A number also adds
  that many degrees.
- **`start` / `end`** travel only part of the path.
- **`align`** (`live` only) lays the path over an element, so the follower moves
  along it where it is drawn. **`alignOrigin`** picks the point of the follower
  that sits on the path.
- Stagger spreads several followers along one path, and `from()` travels it
  backwards.

`live` reads the page once, when the tween is built. The path element's
position and scale and the follower's layout box are stored as a `matrix` on
the track, so the JSON still says exactly where the follower goes.

Measured in Chrome with real layout: followers stay within 0.24 px of the
browser's own geometry for the path.

### Shape morphing from `live`, `tf` and `timeline()`

GSAP's `morphSVG` option:

```ts
const [shape] = live.convertToPath('#circle')
live.timeline({ repeat: -1 })
  .to(shape, { morphSVG: '#star', duration: 1 })
  .to(shape, { morphSVG: '#heart', duration: 1 }, '+=0.5')
```

- **In `live`**, the target shape can be a selector, an element (a path or any
  basic shape) or path data. Each element starts from the shape it currently
  draws, so chained morphs follow on, several elements each morph from their
  own shape, and a numeric `stagger` is honoured.
- **In `tf` / `timeline()`**, `morphSVG` takes path data, and the start comes
  from `fromTo` or an earlier morph. Morphing from nothing throws a clear error.
- **`live.convertToPath()`** replaces circles, ellipses, rects, lines, polylines
  and polygons with equivalent `<path>` elements, keeping their other
  attributes.

The morph engine was rewritten so shapes match up intentionally:

- It picks the start point and winding direction that move points least,
  measured about each shape's centre, like GSAP's `shapeIndex: "auto"`. Nothing
  twists or turns inside out. `shapeIndex` can force a specific alignment.
- Corners of both shapes are always sampled, so star points and square corners
  stay sharp mid-morph. Before, 64 even samples cut them off.
- Paths with the same number of subpaths morph subpath to subpath, so holes
  stay holes.
- Open paths stay open. Before, every morph was closed with `Z`.
- At progress 0 and 1 the original path strings are returned exactly.
- The matching runs once per pair of shapes and is cached. Each frame only
  blends points.

### Inertia: throws, and dragging with a throw

GSAP's InertiaPlugin and Draggable with `inertia: true`:

```ts
live.to('.puck', { inertia: { x: { velocity: 900, max: 400, end: 50 } } })
live.draggable('.card', { bounds: '.table', inertia: { end: slots } })
```

- **A new inertia track** (`kind: 'inertia'`) holds a release velocity,
  friction, optional `min`/`max`, and an `end` snap: a grid size or a list of
  values. Friction is exponential decay, which has an exact closed form, so the
  value at any time is computed directly. There is no simulation and no cache,
  and scrubbing backwards is identical to playing forwards.
- **Snapping keeps the feel.** A throw aimed at a snap point decelerates at the
  same rate and lands exactly on it.
- **Scale-invariant settling.** A 1-unit throw and a 500 px throw with the same
  friction settle in the same time.
- **The `inertia` tween option** accepts a bare velocity or `{ velocity, min,
  max, end, resistance | friction }`. `end` may be a function of where a free
  throw would stop; it runs once at build time. A throw sets its own duration,
  and the next tween starts after it, from where it came to rest.
- **`live.draggable(target, options)`** drags an element (`type`, `bounds` as
  an element or offsets, `snap`) and, with `inertia`, throws it on release
  using the release velocity. `end` can also be a list of `{x, y}` points, and
  the nearest in 2D wins. Picking the element up mid-throw stops it where it
  is. Dragging writes positions straight to the stage with the new
  `Stage.apply()`.
- **In the editor:** **Add Inertia** in the Tracks panel creates one. It shows
  as a span on the timeline, and its inspector shows where it rests and how
  long it takes to settle.
- Inertia tracks bake into keyframes for exports, sharing the sampler with
  springs.

### Text: typing and scrambling

GSAP's TextPlugin and ScrambleTextPlugin options:

```ts
live.to('.title', { text: 'Hello world', duration: 1, ease: 'none' })
live.to('.title', { text: { value: '', rightToLeft: true }, duration: 0.4 })   // backspace
live.to('.code', { scrambleText: { text: 'granted', chars: 'numbers', revealDelay: 0.3 }, duration: 1 })
```

- A new keyframed **text track** holds the start and end text and the options
  in `textConfig`. Its keyframes are eased progress, so easing, delays, stagger
  and sequencing all work as they do for any tween.
- **The scramble is deterministic.** Scrambled characters are a hash of a seed,
  the character's position and the refresh step, never `Math.random`. Scrubbing
  backwards shows exactly the frames that playing forwards did, and exports
  match. The seed defaults to one derived from the target and text.
- Scramble options: `chars` (named sets or your own characters),
  `revealDelay`, `speed`, `tweenLength` and `rightToLeft`. Spaces stay spaces,
  so word shapes remain readable.
- In type mode the new text overwrites the old one character at a time, over
  the longer of the two strings, so typing towards shorter text deletes as it
  goes.
- `live` starts from each element's current text. `tf` starts from the text it
  last set, or from empty.
- The DOM and SVG adapters set `textContent`, skipping the write when the text
  is unchanged. The Canvas adapter already applied `text` to text targets.

### Text animation in the editor

Select a text element and use **Text Animation** to scramble it into new words
or type it on, starting at the playhead. Select the resulting text track to
edit, in its own inspector:

- the From and To words, and right-to-left;
- the character set, including a custom one;
- the refresh rate and reveal delay, and whether the length grows or shrinks;
- **New scramble**, which picks another seeded sequence;
- start, duration and easing.

Edits are undoable and keep the track's place in the track order, which
decides ties between overlapping tracks. The new `Timeline.replaceTrack` does
this, and spring edits now use it too. Text tracks play in every preview and in
raster exports. CSS and Lottie exports leave them out, since neither format can
animate text content.

### Path utilities are public

`tinyfly` now exports its path module: `parsePath`, `getPointAtProgress`,
`getPathLength`, `morphPath`, and two new builders:

- `pointsToPath(points, { curviness, closed })` returns a smooth path through
  the points.
- `shapeToPathData({ tag, attributes })` returns path data for a basic SVG shape,
  starting where the browser's own geometry starts.

## Fixed

### Chained tweens on the same property hid each other

Before this fix, a track reported its starting value for the whole time before
it started, and when several tracks drove one property the last one added
always won. As a result, the second tween in `.to(box, { x: 100 }).to(box, { x: 0 })` applied
its starting value (100) from time zero, and the first tween never showed.

The engine now resolves several tracks on one target and property like this:

1. Of the tracks that have started, the one that started most recently wins.
2. Before any has started, the one that starts first supplies its starting value.
3. Ties on start time go to the track added last, so the documented rule for
   identical spans still holds.

`findConflicts()` and the editor's "overridden track" marker use the same rule.
The fast path is unchanged when every property has only one track. Chained
properties cost about 30% more per track (420 µs for 2,000 tracks).

Two shipped examples were silently affected and now play as written: Split
Text Reveal's wave, and Logo Sequence's entrance spin.

### A repeat delay showed the first frame instead of the last

A forward-looping timeline with `repeatDelay` jumped back to its first frame
and then waited. A finished state (decoded figures, filled bars, a settled
throw) snapped back to where it started for the whole pause. The timeline now
holds its last frame through the pause and then starts over, as GSAP does.
Yoyo loops were unaffected.

### Fast flicks lost their velocity

`Observer`, and so `Draggable`, did not capture the pointer. A quick flick that
left the element's bounds stopped reporting moves and the release, so it lost
its velocity. It now captures the pointer on press.

### Typing into a text element's Content field was undone every keystroke

In the editor, the Content and Font fields reset on every keystroke, so the
new text never took. Their sync effect tracked the field's own value as well
as the element's, so each keystroke re-ran it before the update landed, and it
put the old text back. The effect now tracks only the element's value.

The DOM and SVG adapters also now update an element's single text node in
place instead of replacing it. A framework that rendered the text (the
editor's preview, or a React or Solid app) keeps its reference to that node and
stays in control of it. The editor preview puts an element's own text back
once a text track stops driving it.

### Start values in the GSAP facade

- Chaining now remembers colours and shapes, not just numbers, so
  `.to(box, { backgroundColor })` after an earlier colour tween starts from that
  colour.
- A fallback start value of the wrong kind (0 for a colour) used to render
  garbage, such as black, for the whole tween. The tween now snaps to its end
  value and warns, pointing at `fromTo()`.

## Changed

### A path parser that handles real paths

The old parser missed much of what design tools export. It could not read
compact numbers (`10-20`, `.5.5`) or exponents. It dropped repeated coordinates
after `M`, `L`, `H`, `V` and `A`. It drew `S` and `T` smooth curves as straight
lines. And within a curve it moved by the bezier's `t`, so speed changed
wherever control points were close together.

The rewrite converts every command to absolute lines and cubic beziers.
Quadratics become exact cubics, `S` and `T` reflect the previous control point
as the SVG spec defines, and arcs become cubic pieces of at most 90°. A length
table per curve makes progress even along curves. The parse cache is now
bounded. Shape morphing uses the same parser, so it benefits too.

`MotionPathConfig` has a new optional `matrix`. It applies an affine transform
to every point on the path and to its tangent.

## Upgrade Notes

Upgrade from v0.52.0: no API removed and no data migration, but three
behaviours change:

- **Several tracks on one property** now play in start order, rather than the
  last added covering the others. A timeline that relied on a later-added track
  overriding an earlier-starting one for their whole overlap will look
  different. Tracks with identical spans resolve as before.
- **Paths** that use `S`, `T`, compact notation or repeated coordinates now
  follow their true shape instead of a simplified one.
- **Morphs** keep corners, stay open for open paths, and choose their start
  point, so mid-morph frames differ from before, while endpoints are unchanged.
- **Repeat delays** now show the timeline's last frame during the pause, not
  its first.
