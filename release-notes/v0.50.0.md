# v0.50.0

**Release Date:** 2026-09-12

One-click spring presets, and the runtime-stagger question finally settled with
a measurement instead of an assumption.

## Spring presets

`PresetTrack` was keyframe-shaped, which meant the Presets panel could not offer
springs at all. It is now a union — `KeyframePresetTrack | SpringPresetTrack` —
so a single preset can mix both kinds. Most of the new ones do: a keyframed
opacity fade alongside a spring on scale or position.

Five presets in a new **Spring** category:

| Preset | What it does |
|---|---|
| **Spring Pop** | Scales up from nothing with an overshoot — the classic "pop in" |
| **Spring Drop** | Falls in from above and bounces to a stop |
| **Spring Slide** | Slides in from the left and settles with a small overshoot |
| **Spring Wobble** | A flick of rotation that wobbles back to rest |
| **Spring Settle** | Critically damped: arrives fast, stops dead, no overshoot |

Two of them exist to demonstrate the physics rather than just to look nice.
**Spring Wobble** has `from === to` with a non-zero `velocity`, so the motion
comes entirely from the initial flick — that is what makes it read as a *knock*
rather than a return from somewhere. **Spring Settle** is damped past critical,
making it the counterexample to the other four. Both characteristics are
asserted in tests, so an edit that quietly breaks them fails rather than merely
looking a bit different.

Springs stagger by their `delay`, since they have no keyframes to shift, so the
per-letter stagger works on them like any other preset. Applying one extends the
scene to fit the settle time.

## The runtime-stagger evidence gate, resolved

v0.47.0 shipped runtime stagger while explicitly recording that its own spec had
said *do not add a second way to express stagger without a profile showing the
baked form is too slow* — and that no profile had been run. That has now been
done, and **the answer was not what the spec expected**:

| targets | baked eval | runtime eval | baked JSON | runtime JSON |
|---|---|---|---|---|
| 10 | 5.9 ms | 3.5 ms | 1,176 | 251 |
| 100 | 8.1 ms | 7.0 ms | 11,676 | 792 |
| 500 | 41.3 ms | 41.9 ms | 59,626 | 3,593 |

**Speed is not the reason.** The two forms are within noise of each other and
identical at 500 targets — expanding one track across N targets costs about what
evaluating N tracks costs, which is exactly what you would expect.

**File size is the reason**, and it is not close: roughly 15× at 100 targets and
17× at 500. A 500-letter split is 59 KB of JSON baked and 3.5 KB as one track.
For a format whose whole point is being shipped over a network and stored per
project, that justifies the feature — just on different grounds than assumed.

The practical consequence: **the editor should keep baking.** The baked form is
what makes each letter's keyframes individually draggable, and inside an editor
that authorability is worth more than the bytes. The runtime form is for the API
and for what you ship.

A follow-on idea is recorded but not built: an export-time pass that collapses a
set of identically-shaped, evenly-offset tracks back into one runtime stagger
track, giving small files *and* per-letter editing.

The timings are kept as a comment rather than asserted — timing assertions in CI
are flaky and there is no action anyone would take on them. The size
relationship *is* asserted, because it is deterministic and it is the property
the feature exists for.

### Test Coverage

- **1174 tests passing (1155 → 1174)** — 19 new
- Mixed presets build the right track kind for each entry
- Spring presets stagger via `delay`, and a staggered spring preset still
  extends the scene past the last spring
- Round-trip with parameters intact
- Wobble's velocity-driven characteristic and Settle's critical damping, both
  asserted rather than assumed
- Runtime and baked stagger produce identical values at every sampled target and
  time, with the size gap asserted and shown to widen with target count

## Upgrade Notes

Upgrade from v0.49.0:

1. No data migration.
2. `PresetTrack` is now a union. Code that reads `track.keyframes` off a preset
   track must narrow first:
   ```ts
   import { isSpringPresetTrack } from './presets'
   if (!isSpringPresetTrack(track)) { /* track.keyframes is available */ }
   ```
3. `AnimationPreset['category']` gains `'spring'`.
