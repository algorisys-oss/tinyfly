# v0.19.0

**Release Date:** 2026-07-22

The **My Animations gallery** lands: every animation you make is saved, browsable
with thumbnails, and one click away — backed by IndexedDB instead of a single
LocalStorage slot. Plus **collapsible side panels** for a bigger canvas.

## Highlights

- **My Animations gallery.** A new toolbar button opens a grid of every project
  you've saved — each card shows a live thumbnail, name and "last modified". Open
  one to keep editing, **duplicate**, or **delete** it. The project you're
  editing is badged so you never lose your place.
- **IndexedDB persistence.** Projects (and their thumbnails) now live in
  IndexedDB, lifting the old ~5 MB LocalStorage ceiling that a few
  media-heavy animations could hit. Anything already saved in LocalStorage is
  **migrated automatically** on first run, and the store falls back to
  LocalStorage where IndexedDB isn't available (e.g. some private-mode browsers).
- **Collapsible panels.** Hide the **Elements/Tracks** and **Properties/Presets**
  columns with a click to give the canvas room to breathe; a slim tab brings each
  one back.
- **Rename inline + explicit Save.** Double-click the project title in the
  toolbar to rename it in place. A new **Save** button shows a clear status —
  **Save** (accented) when there are unsaved changes, **Saving…**, then a calm
  green **Saved ✓** — so touch/tablet users get an obvious, tappable save even
  though auto-save still runs in the background.
- **Gallery route branding.** The `/gallery` examples page now carries the
  **tinyfly** wordmark and **BETA** badge, matching the editor header.

## Why this was needed

Until now the editor auto-saved to a **single** LocalStorage project. Start
something new and your previous animation was effectively gone unless you'd
exported JSON. The gallery makes tinyfly a place you can accumulate work: every
animation is kept, thumbnailed, and reopenable — the workflow people expect from
a real design tool.

## Added

- **`GalleryDialog`** (`src/editor/components/gallery-dialog.tsx`) — the
  "My Animations" grid: thumbnails, relative timestamps, open/duplicate/delete,
  inline delete confirmation, and a "New" action.
- **IndexedDB backend** (`src/editor/stores/project-persistence.ts`) —
  `openIndexedDbBackend()` opens a `tinyfly` database with `projects`,
  `thumbnails` and `meta` object stores, hydrates in-memory snapshots for
  synchronous reads, writes through asynchronously, and migrates legacy
  LocalStorage projects on first run.
- **Pluggable `ProjectBackend`** interface in `project-store.ts` — the store now
  takes an optional backend; the default remains synchronous LocalStorage.
- **Scene thumbnails** (`src/editor/utils/scene-thumbnail.ts`) —
  `renderSceneThumbnail()` renders a scene's poster frame with the Canvas export
  compositor (images, video first-frame, gradients, rounded corners) to a WebP
  data URL.
- Collapsible left/right side panels in the editor, with reveal tabs.
- Inline project-title rename (double-click) and a **Save** button with
  Save / Saving… / Saved ✓ status in the toolbar.
- tinyfly wordmark + BETA badge on the `/gallery` route header.

## Changed

- `createProjectStore()` accepts `{ backend }`; the editor opens the IndexedDB
  backend before mounting (with a short loading splash) and injects it.
- Deleting a project also drops its stored thumbnail.

## Fixed

- Pre-existing type errors that broke `npm run build` after a toolchain bump
  (an unused import and two attribute/fixture type mismatches) — the production
  build is green again.

### Architecture

The engine is untouched — this is entirely an editor-layer feature, consistent
with tinyfly's loose-coupling rule. The project store keeps its in-memory `Map`
as the session source of truth (so reads stay synchronous); the IndexedDB
backend pre-loads a snapshot at open time and writes through asynchronously,
diffing by object identity so only changed projects are persisted.

### Test Coverage

- 613 tests passing (+9): a `ProjectBackend` integration suite driving the store
  through an in-memory backend (hydrate, save-through, thumbnail get/set/delete,
  `clearAll`), and thumbnail-render guard tests (empty scene, hidden/group-only,
  zero-sized canvas, graceful no-context fallback).
