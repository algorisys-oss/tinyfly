# v0.24.0

**Release Date:** 2026-07-22

**Edit symbols in place** — the piece that makes Symbols truly
"edit-once-update-everywhere."

## Highlights

- **Edit-in-place.** Double-click a symbol **instance** on the stage (or click the
  **pencil** on a Library item) to open the symbol. The stage and timeline switch
  to the symbol's own contents, and a **breadcrumb** appears:

  ```
  ‹ Scene 1  ▸  🔷 My Symbol      editing symbol — changes apply to all instances
  ```

  Edit the elements and the symbol's own timeline as usual — **every instance
  updates** to match. Click the scene name (or `‹`) to return. It all auto-saves.
- **Safe context switching.** Saving while editing a symbol writes to the symbol
  definition (not the scene); opening the gallery, switching or creating a project
  cleanly exits symbol mode first, so edits never land in the wrong place.

## Added

- Symbol **edit-in-place** context in the editor: `enterSymbol` / `exitToScene`,
  a breadcrumb (replacing the Scene Bar while editing), and auto-save/flush that
  branch to `updateSymbol` when a symbol is open.
- Entry points: **double-click an instance** in the DOM preview
  (`PreviewPanel.onEditSymbol`) and an **Edit** button per Library item.

## Changed

- Thumbnail capture is skipped while editing a symbol (so the scene/gallery
  thumbnail isn't overwritten with symbol contents).

### How it works

The editor keeps an **edit context** (`scene` or `symbol`). Entering a symbol
loads its elements + timeline into the same scene/editor stores; auto-save and
flush write back via `projectStore.updateSymbol`. A backstop effect drops out of
symbol mode if the current project changes by any path. The engine is untouched —
symbols remain plain JSON on the project.

### Test Coverage

- 634 tests passing (the symbol store API, including `updateSymbol`, is covered by

  those tested calls).
