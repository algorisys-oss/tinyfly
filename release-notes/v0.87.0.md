# v0.87.0

**Release Date:** 2026-10-05

Two tools for viral loops: a check that a video really loops, and a bloom
glow for neon looks.

## Added

- **`tinyfly video scene.mjs --loop-check`**: renders five frames (no ffmpeg)
  and says whether the video *closes* (the frame at the duration matches the
  first), is *seamless* (the last → first step looks like any other step), or
  *does not loop* (exit 1, so a build can check it). From code:
  `checkLoop(scene)`, and the pure `psnr(a, b)` / `loopReport(frames)`.
- **Stills at chosen frames**: `--stills dir --frames 0,79,88` (or `--times`
  in ms).
- **Bloom**: `bloom: true` (or `{ threshold, strength, radius, halo,
  downsample }`) on a video scene adds a glow around bright things. A bright
  pass that keeps each pixel's hue, a separable box blur, a tight glow plus a
  wide halo, added back: plain arithmetic, no `ctx.filter`, so every frame is
  the same on every machine. `applyBloom(ctx, options)` works on any 2D
  canvas (`@algorisys/tinyfly/adapters` and the browser bundle).
- **Emissive 3D materials**: `emissive: '#ff2bd6'` is light the surface gives
  off itself, added after lighting in both the Canvas 2D and WebGL2
  renderers. It shows in the dark and feeds the bloom.
- Example `examples/headless-video/neon-bloom.mjs`: a looping neon scene.

## Fixed

- `stillTimes()` no longer throws for a timeline without `config`.

## Technical Details
