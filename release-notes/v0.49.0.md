# v0.49.0

**Release Date:** 2026-09-12

Springs become authorable. Add one from the Tracks panel, tune it with presets
and sliders in Properties, and watch the curve update — no API calls needed.

## Spring authoring in the editor

Springs have been playable since v0.47.0 and drawable since v0.48.0, but they
could only be *created* through the API. That gap is closed.

**Tracks → + → Add Spring** creates a spring for a target and property. Select
it and the Properties panel shows a spring inspector:

- **Feel presets** — Gentle, Default, Snappy, Bouncy, Wobbly, Stiff. Stiffness
  and damping interact, so named pairs that are known to work are far more
  useful as a starting point than two bare sliders someone has to discover the
  combinations of.
- **Values** — from, to, and a start delay.
- **Physics** — sliders for stiffness, damping and mass, plus an initial
  velocity field (a flick at the start).
- **Settle time**, and an **overshoots** badge when the spring is underdamped.

## Three decisions worth recording

**Editing replaces the track rather than mutating it.** `Timeline` builds a
memoised `SpringSampler` when a spring track is added — that memoisation is what
makes scrubbing cheap. Mutating `track.spring` in place would leave the old
simulation cached, so the preview would keep showing the previous motion while
the numbers in the panel said otherwise. `updateSpring` removes and re-adds, and
there is a test asserting that an edit actually changes the sampled values.

**The scene grows to fit the spring.** A spring decides its own duration — a
looser one simply takes longer to settle — so an edit that slows one down has to
extend the scene or its tail is silently cut off. This needed a new
`requiredDurationMs()` on the store, because the existing `lastKeyframeTime()`
only sees keyframes and a spring has none: a spring-only scene would have
computed a duration of 0 and played nothing at all.

**The "overshoots" badge is engine physics, not UI arithmetic.** Whether a
spring passes its target is `damping < 2 * sqrt(stiffness * mass)` — exact, and
free compared to simulating. That now lives in the engine as `isUnderdamped`
(with `criticalDamping` alongside), and a test checks the closed form against
the actual simulation across a range of parameters. A badge that lied about
overshoot would be worse than no badge.

### Test Coverage

- **1155 tests passing (1134 → 1155)** — 21 new
- The cached-sampler rebuild (the bug the replace-don't-mutate design avoids)
- `requiredDurationMs` accounting for springs, and taking the later of keyframes
  and springs
- Scene growth when an edit makes a spring slower to settle
- Undo, JSON round-trip with parameters intact, and no-ops for non-spring and
  missing tracks
- `isUnderdamped` agreeing with the simulation over five parameter sets, plus
  mass sensitivity and behaviour at exactly critical damping

### Verification note

The Playwright browser profile was held by another session throughout this work,
so the spring inspector's **visual layout has not been checked by eye**. It is
covered by the test suite, a clean typecheck, a successful production build, and
HTTP checks that every touched module transforms without error and contains the
expected markup. If the panel looks wrong when you open it, that is where to
look first.
