# v0.54.1

**Release Date:** 2026-09-13

Cross-browser testing, and a fix it found on the first run.

Until now tinyfly had only been run in Node and in Chromium. This release adds
a suite that runs it in real Chromium, Firefox and WebKit and measures the
results.

## Fixed

### SVG content rotated around the corner of the drawing, not in place

A `rotate` or `scale` on an SVG element (a `<rect>`, `<path>` or `<g>`) pivoted
around the SVG's own origin, its top-left corner. That happened in both the
SVG adapter and the DOM adapter unless an origin was also animated. HTML
elements and canvas shapes pivot on their own centre, so the same animation
looked different depending on where it ran. `live.to('svg rect', { rotate: 90 })`
also swung the rect across the drawing instead of turning it, unlike GSAP.

Both adapters now default SVG content to its own box and centre
(`transform-box: fill-box`, `transform-origin: 50% 50%`), so every renderer
agrees. An origin set by the author, inline or through an origin track, still
takes precedence. The editor's SVG preview had been hiding the problem with
inline styles on its own markup.

## Added

### `npm run e2e`: cross-browser checks

```bash
npx playwright-core install firefox webkit   # once; Chromium uses the installed Chrome
npm run e2e
npm run e2e -- --browser firefox --check demos
```

The runner starts the dev server, and checks import tinyfly's source modules
into a blank harness page, so they test the code as written in each engine
without a build. The checks measure outcomes rather than only looking for
errors:

| Check | What it measures |
|---|---|
| engine | Determinism in any sampling order, inertia snapping, the path parser against the browser's own `getTotalLength` and `getPointAtLength`, and `structuredClone` |
| adapters | DOM transform composition by bounding box, shine clipped to the glyphs by pixel, SVG rotation about its own centre by bounding box, and canvas drawing by pixel |
| exports | GIF, WebP and MP4 (WebCodecs) produce valid files. A capability the browser lacks is reported as a note |
| demos | All 33 GSAP-style demos animate under real mouse input, motion-path followers stay on the drawn path, and Flip neither jumps nor misses |
| editor | Adding elements, typing content, playing in DOM, Canvas and SVG, and IndexedDB persistence across a reload |

## Results

| | Chromium 150 | Firefox 153 | WebKit 26.5 |
|---|---|---|---|
| Checks passing | 19 / 19 | 19 / 19 | not run: the host is missing `libavif16` |
| Path geometry vs native (worst) | 0.025 px | 0.025 px | — |
| Motion path followers (worst) | 0.32 px | 0.32 px | — |
| Flip first-frame jump | 0.00 px | 0.00 px | — |
| MP4 export | yes | yes | — |

The results in Chromium and Firefox are identical to the hundredth of a pixel.
That is the practical result of computing geometry in the engine rather than
reading it from the browser. On Linux, WebKit needs
`sudo apt-get install libavif16`, after which `npm run e2e -- --browser webkit`
runs it.

## Technical Details

| File | Description |
|------|-------------|
| `e2e/run.mjs` | Starts the dev server, runs each check in each browser, prints a table, and exits non-zero on failure |
| `e2e/checks/*.mjs` | The engine, adapters, exports, demos and editor checks |
| `e2e/harness.html` | Blank page that checks import source modules into |
| `src/adapters/svg-transform-box.ts` | Makes SVG content pivot in place by default |
| `package.json` | `playwright-core` 1.62.1 (pinned; no test framework or bundled browsers) and `npm run e2e` |

### Test Coverage

- 4 unit tests for the SVG pivot default: it is applied, an author's origin is
  left alone, HTML elements are untouched, and both adapters use it.
- 1,622 unit tests passing, plus the 19 cross-browser checks per browser.

---

## Upgrade Notes

Upgrade from v0.54.0: SVG elements that are rotated or scaled, without an
origin set, now turn in place instead of around the SVG's top-left corner. If
you relied on the old pivot, set `transform-origin` (or `transform-box:
view-box`) on the element.
