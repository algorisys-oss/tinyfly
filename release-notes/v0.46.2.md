# v0.46.2

**Release Date:** 2026-07-31

Consistency pass over the timeline: the skipped auto-save now retries itself, and
the track-label width has one definition instead of four.

## Auto-save retries the save it skipped

v0.46.1 fixed the auto-save effect unsubscribing itself mid-switch. The guard it
uses, `isSwitchingScene`, was still a plain variable, so lowering it re-armed
nothing — the save skipped during a switch waited for the user's next edit.

It is now a signal. The effects subscribe to it, so the moment a scene or project
switch finishes they re-run and persist the state they skipped.

## One definition of the track-label width

The label column at the left of the timeline sets the origin every hit test
measures from. Its width was written down in four places: `120` in
`timeline-panel.tsx`, `120` in `curve-view.tsx`, a measured offset in
`timeline-view.tsx`, and CSS rules that narrow the column to 90px and 70px at the
mobile breakpoints. The JS copies never saw the narrowing, so on a phone:

- box-select in **Curves** tested keyframes against an origin 30–50px off;
- the timeline's zoom-at-cursor anchored to the wrong time;
- the horizontal scrollbar's padding did not line up with the lanes.

Worse, v0.46.0 made the ruler gutter follow `.track-label` responsively while
`.curve-lane-label` stayed pinned at 120px — so on narrow screens the curve lanes
drifted out of line with the shared ruler.

The width is now a single CSS custom property, `--track-label-w` on
`.timeline-panel`, which the dope-sheet labels, curve-lane labels, ruler gutter
and scrollbar all size off. A new `trackLabelWidth()` helper reads it back for
hit-testing, climbing to the panel that declares it rather than relying on
inherited-value resolution, and falling back to the desktop width rather than
collapsing to 0 when it is unavailable.

## Technical Details

| File | Description |
|------|-------------|
| `src/editor/editor.tsx` | `isSwitchingScene` is a signal, so a skipped auto-save/thumbnail run retries when the switch ends |
| `src/editor/utils/track-label-width.ts` | New `trackLabelWidth()` / `DEFAULT_TRACK_LABEL_WIDTH` |
| `src/editor/components/timeline-panel.css` | Declares `--track-label-w` (120/90/70 across breakpoints); scrollbar padding uses it |
| `src/editor/components/timeline-view.css` / `curve-view.css` | Labels and ruler gutter size off the property; breakpoints now only tune padding |
| `src/editor/components/timeline-panel.tsx` / `curve-view.tsx` / `timeline-view.tsx` | Hit tests, zoom anchor and viewport width read the shared width |

### Test Coverage

- 731 tests passing (724 → 731)
- 7 new tests for `trackLabelWidth`: desktop and both mobile widths, lookup from a
  descendant, element outside a panel, missing property, unparseable value, and
  no element at all.

### Audit note

Every other `createEffect` in the editor was checked for the v0.46.1 defect
(returning before reading a tracked signal). The rest guard on a signal read —
`if (!dragging())`, `if (props.isOpen)`, `if (isDirty() && autoSaveEnabled())` —
which subscribes as it tests, so they are unaffected.
