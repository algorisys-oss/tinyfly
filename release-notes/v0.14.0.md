# v0.14.0

**Release Date:** 2026-07-11

Patch/minor release that makes **video export capture DOM-composited layers** —
images and video (e.g. a device screen's recording) now appear in the exported
file, not just shapes and text.

## Highlights

- **Image & video layers in exported video** - The Canvas video exporter now
  composites `image` and `video` elements by drawing them with `ctx.drawImage`.
  Video layers are **seeked in sync** with the timeline (respecting each clip's
  start time and loop), so a phone-mockup screen playing a screen-recording is
  captured in the MP4/WebM output.

## Added

- **`buildExportComposite(elements)`** (`utils/export-composite.ts`) -
  Pre-loads image/video sources, registers them as Canvas image targets in
  z-order, and exposes `prepareFrame(timeMs)` to seek videos before each frame.
- **`exportToVideo` supports an async `renderFrame`** so frames can await video
  seeks.

## Changed

- The Export dialog's video renderer uses the composite, so the "video layers are
  DOM-only" caveat is gone — images and video are captured.

## Technical Details

### Changed Files

| File | Description |
|------|-------------|
| `src/editor/utils/export-composite.ts` | Pre-load + composite image/video layers; per-frame video seeking |
| `src/editor/components/export-dialog.tsx` | Use the composite; async renderFrame |
| `src/engine/export/video.ts` | `renderFrame` may return a Promise (awaited per frame) |

### Test Coverage

- 531 tests passing. Verified live in Chrome: a scene with a video layer exported
  to an MP4 whose frames show the clip's moving content (frame counter 7 → 28),
  proving the video was composited and seeked in sync.

### Known limitations (tracked in todo.md)

- The Canvas draw path doesn't yet honour a video/image `objectFit` (fills the
  box) or a rounded-corner clip (`borderRadius`), so a device screen won't show
  cover-cropping or rounded corners in the exported file.
- Video sync uses per-frame seeking (approximate for long clips).

## Upgrade Notes

Upgrade from v0.13.0:

1. No breaking changes.
2. Cross-origin image/video sources need CORS to avoid tainting the export
   canvas; same-origin and data-URI sources always work.
