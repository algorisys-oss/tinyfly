# v0.69.0

**Release Date:** 2026-09-15

A teaching figure can now hold several timelines, and the reader picks which one plays:
a request with and without a cache, a cluster before and after its leader fails, one
server against ten.

## Added

### Scenarios

- **Markup:** put several `data-tinyfly-timeline` scripts in one figure, each with a
  `data-scenario` id and an optional `data-scenario-label`. On the figure,
  `data-scenario` picks the first one shown, `data-scenario-legend` names the choice, and
  `data-scenario-control` is either `buttons` (the default, a radio group) or `slider`
  (a range input with one stop per scenario).
- **Hotspots:** mark any element inside the SVG with `data-tinyfly-choose="id"` and it
  becomes a toggle button (`role="button"`, `aria-pressed`, keyboard support) that
  switches to that scenario. Works with `data-controls="false"` too.
- **Switching:** the previous scenario's styles, text and path geometry are undone
  before the new one draws. The reader stays on the same step when the new scenario has
  a marker with the same id. The end stays the end, playing stays playing, and reduced
  motion shows the final frame.
- **Player API:** `loadScenarios`, `scenarios`, `scenario`, `setScenario`.
- **Embed API:** `createControls` takes `scenarioControl` and `labels.scenario`;
  `bindChoiceHotspots(player, figure)` returns an unbind function.
- **Tools:** `validateScenarios`, and `tinyfly validate` accepts several timeline files.
- See [Scenarios in docs/teaching.md](../docs/teaching.md#scenarios-let-the-reader-change-something).

## Fixed

### Controls stopped updating after a second load

- **What was wrong:** `watchVisibility` cleared the player's subscribers on every
  `load()` (a stray `listeners.clear()` from v0.64.0), so the play button and scrubber
  froze after the figure loaded a second timeline.
- **Now:** subscribers survive a reload.
