Bottom line

tinyfly covers ~85% of the GSAP surface area needed for Awwwards-level work. All the core motion techniques — scroll scrubbing, pinning, split-text reveals, springs, inertia, SVG morphing, motion paths, Flip — are implemented and tested. The gaps are runtime dynamism (per-frame function values, ScrollSmoother), a handful of polish features (page transitions, image-sequence scrubbing), and an ecosystem that is still pre-v1. For greenfield award-site work it is production-capable today; for drop-in GSAP replacement it is not.

Awwwards Signature Patterns — Coverage

✅ Fully Covered

  • Scroll-scrubbed entrance reveals (ScrollDriver + stagger)
  • Pinned horizontal scroll panels
  • Letter-by-letter / line-masked text reveals (SplitText)
  • Smooth cursor follower with lag (quickTo trail)
  • Magnetic button attraction (proximity + spring)
  • macOS dock magnification effect
  • SVG path drawing reveals (drawSVG)
  • Icon morphing on hover (morphSVG)
  • Animate along SVG path (motionPath + autoRotate)
  • Spring-based UI feedback (5 named presets)
  • Card shuffle with Flip layout animation
  • Shared-element gallery transitions (data-flip-id)
  • Velocity skew on scroll
  • Swipeable card stacks with inertia throw
  • Infinite marquee / looping ticker
  • Canvas 2D custom objects animated
  • 3D card flip (perspective)
  • Counter / stats number reveal
  • Reduced motion detection (matchMedia)
  • Scramble text effect

⚠ Partial / Workaround Needed

  • Smooth scroll parallax — works with Lenis via driver.update(), but no built-in ScrollSmoother
  • Elastic / bounce eases — baked to keyframes at author-time (visual result is equivalent)
  • Runtime random values — compile-time only; can't vary each loop iteration at runtime
  • Image-sequence video scrubbing — planned Phase 28B.5; manual drawImage loop needed today
  • steps() easing — baked to intermediate keyframes
  • React/Vue lifecycle cleanup — live.context() exists but no useGSAP()-style hook yet

❌ Not Yet Available

  • Built-in page / route transition system (Phase 28B.6, planned)
  • ScrollSmoother (smooth scroll + parallax layers)
  • Per-frame function values (gsap.utils.pipe, per-update random)
  • npm package (CDN or local build only)
  • Framework wrappers (@tinyfly/react, etc.)
  • Community plugins / ecosystem

🔵 tinyfly Ahead of GSAP

  • Visual keyframe editor with live scroll-preview built-in
  • All animations portable as plain JSON (designer ↔ developer handoff)
  • Export: CSS keyframes, Lottie, GIF, WebP, MP4, sprite sheet
  • Canvas 2D & WebGL animation targets (GSAP is DOM/SVG only)
  • Gradient animation built-in (no plugin needed)
  • Deterministic engine — no getComputedStyle surprises
  • Spring tracks are serializable and editable in the editor
  • Aria-aware SplitText (screen reader correct by default)
  • Grapheme cluster support in SplitText (emoji-safe via Intl.Segmenter)

The Key Principled Difference

The Determinism Rule

tinyfly's most important architectural divergence from GSAP: no getComputedStyle. No per-frame function values. Values are resolved at compile time and written into JSON.

  • ›fromTo() is strongly preferred — always provide both start and end values. tinyfly logs a dev warning if it falls to a static default; GSAP silently reads the computed style.
  • ›No repeatRefresh — values don't re-resolve each loop iteration.
  • ›No runtime random — gsap.utils.random() inside vars is rejected; use compile-time equivalent.
  • ›Upside: Any animation round-trips as JSON, opens in the editor, plays identically everywhere, and is fully inspectable.

🏆 Final Verdict

  1. Greenfield award site today: tinyfly has every technique you need — scroll scrubbing, pinning, split-text, springs, magnetic cursors, SVG draw, morphing, Flip, shared elements. You won't hit a wall on any standard Awwwards pattern.
  2. API familiarity: If you know GSAP, tinyfly's live.* API is near-identical for the 90% case. The main adjustment: always use fromTo() with explicit start values since tinyfly never calls getComputedStyle.
  3. Real gaps for complex award sites: (a) No ScrollSmoother — use Lenis with driver.update(scroll); (b) No built-in page transitions — roll your own with Flip + live.context(); (c) Elastic/bounce eases are "baked" — visually equivalent but keyframe-heavy in JSON.
  4. Unique tinyfly advantage: The visual editor genuinely helps with timing complex scroll sequences. JSON-portability means designers and developers can share and inspect animations — and you get Lottie/GIF/MP4 export for free.
  5. Not a drop-in GSAP replacement: Code does not port unchanged. The determinism rule is a principled constraint, not a bug — but it requires a mental model shift from GSAP users.
  6. Maturity caveat: v0.55, not yet on npm, smaller community. For client production sites that need long-term support, this is the honest risk to weigh against GSAP's proven track record.
